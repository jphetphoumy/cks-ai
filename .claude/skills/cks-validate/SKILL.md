# Goal

Parse the `## Validation` section of a given CKS lab file, write a self-contained validation script, copy it to the master node, execute it, and present the results as a clean pass/fail table — without making repeated SSH calls for individual checks.

# Workflow

## 1. Read the lab file

Read the lab file passed by the user (e.g. `labs/LAB_03_service_accounts.md`).

Extract ONLY the content under the `## Validation` section — every command block between `## Validation` and the next `##` heading.

## 2. Generate the validation script

Write a bash script to `/tmp/cks-validate-<LAB_ID>.sh` locally.

The script structure must be:

```bash
#!/usr/bin/env bash
# CKS Validation — <LAB_ID> <LAB_NAME>
# Auto-generated by cks-validate skill

set -uo pipefail

PASS=0
FAIL=0

check() {
  local desc="$1"
  local cmd="$2"
  local expect="${3:-}"   # optional: expected output substring

  if output=$(eval "$cmd" 2>&1); then
    if [[ -z "$expect" ]] || echo "$output" | grep -q "$expect"; then
      echo "  PASS  $desc"
      ((PASS++))
    else
      echo "  FAIL  $desc"
      echo "        expected: $expect"
      echo "        got:      $output"
      ((FAIL++))
    fi
  else
    echo "  FAIL  $desc"
    echo "        error: $output"
    ((FAIL++))
  fi
}

echo ""
echo "=== CKS Validation: <LAB_ID> ==="
echo ""

# --- checks from lab Validation section ---
<GENERATED_CHECKS>

echo ""
echo "Results: $PASS passed, $FAIL failed"
if [[ $FAIL -eq 0 ]]; then
  echo "All checks passed."
else
  echo "Fix the failing checks and re-run."
fi
```

Replace `<GENERATED_CHECKS>` with `check` calls derived from the lab's Validation section. Each command from the lab becomes one `check` call:

- The description is a short human-readable label derived from the inline comment in the lab
- The command is the exact kubectl/shell command from the lab
- The expected value is the inline comment after `# should` or `# expect` in the lab (e.g. `# yes`, `# false`, `# should fail`)

Example transformation:
```bash
# Lab validation line:
kubectl auth can-i list pods --as=system:serviceaccount:apps:metrics-reader -n apps  # yes

# Becomes:
check "metrics-reader can list pods in apps" \
  "kubectl auth can-i list pods --as=system:serviceaccount:apps:metrics-reader -n apps" \
  "yes"
```

## 3. Copy and run the script on the master node

```bash
scp /tmp/cks-validate-<LAB_ID>.sh $SSH_USER@$MASTER_IP:/tmp/
ssh $SSH_USER@$MASTER_IP 'sudo bash /tmp/cks-validate-<LAB_ID>.sh'
```

## 4. Present results

Show the full output from the script to the user.

If all checks pass: confirm the lab is complete and remind the user to move to the next lab.

If any checks fail: list only the failing checks with their error output, and give a targeted hint for each one — do not re-explain passing checks.

## 5. Clean up

Remove the script from both local and remote after execution:

```bash
rm /tmp/cks-validate-<LAB_ID>.sh
ssh $SSH_USER@$MASTER_IP 'rm /tmp/cks-validate-<LAB_ID>.sh'
```
