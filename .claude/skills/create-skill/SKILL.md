---
name: create-skill
description: Meta-skill — interactively scaffolds a new Claude skill following the project's SKILL.md format (frontmatter + goal + numbered workflow + optional companion script).
disable-model-invocation: false
allowed-tools: Bash, Read, Write, AskUserQuestion
---

# Goal

Scaffold a new skill under `.claude/skills/<name>/` by gathering requirements from the user, generating a well-structured `SKILL.md`, an optional companion shell script, and registering the skill in `settings.local.json`.

# Workflow

## 1. Locate the project root

Find the skills directory relative to this skill file:

```bash
SKILLS_DIR="$(dirname "$(dirname "$0")")/skills"   # .claude/skills/
SETTINGS="$(dirname "$(dirname "$0")")/settings.local.json"  # .claude/settings.local.json
echo "Skills dir : $SKILLS_DIR"
echo "Settings   : $SETTINGS"
ls "$SKILLS_DIR"
```

Use `Read` to inspect an existing skill for reference:
```bash
cat "$SKILLS_DIR/cks-setup/SKILL.md"
```

## 2. Gather requirements from the user

Use `AskUserQuestion` with **two questions in a single call**:

**Question 1 — Skill identity**
Ask: "What should the new skill be named and what will it do?"
Header: "Skill identity"
Options (4 max — user will likely pick "Other" and type freely, but provide anchors):
- `Quick command wrapper` — wraps one or a few shell commands with a friendly interface
- `Environment setup` — checks and installs tools or configures an environment
- `Interactive workflow` — multi-step guided process with decisions and branching
- `Report / audit` — reads state, formats and presents a report to the user

**Question 2 — Companion script**
Ask: "Does this skill need a companion shell script (like setup.sh)?"
Header: "Companion script"
Options:
- `Yes — generate a setup.sh template` — skill will reference $SKILL_DIR/setup.sh
- `No — SKILL.md only` — all logic stays inside the SKILL.md workflow instructions

After the user answers, ask **one more targeted question** about the workflow:

**Question 3 — Workflow steps**
Ask: "Describe the workflow steps for this skill (what should Claude do, in order)?"
Header: "Workflow"
Options (anchors only — user will use Other):
- `Check → report → ask → act` — inspect state, show results, ask permission, then execute
- `Ask → generate → write → confirm` — gather input, produce content, write files, show result
- `Run → stream output → verify` — execute a script, stream its output, then verify success
- `Custom` — I'll describe the steps myself

## 3. Determine allowed tools

Based on the skill type and workflow, decide which tools to list in `allowed-tools`:

| Skill type            | Typical tools                          |
|-----------------------|----------------------------------------|
| Environment setup     | Bash, AskUserQuestion                  |
| Report / audit        | Bash, Read, AskUserQuestion            |
| Content generation    | Read, Write, AskUserQuestion           |
| Full interactive      | Bash, Read, Write, Edit, AskUserQuestion |

## 4. Write SKILL.md

Create `.claude/skills/<name>/SKILL.md` using the `Write` tool.

The file MUST follow this exact structure:

```
---
name: <slug>
description: <one sentence — what the skill does and when to invoke it>
disable-model-invocation: false
allowed-tools: <comma-separated tool list>
---

# Goal

<2–4 sentences explaining the purpose and end state>

# Workflow

## 1. <First step title>

<Instructions for Claude. Use imperative voice. Include bash code blocks where relevant.>

## 2. <Second step title>

<...>

## N. <Final step>

<Always end with a verification or confirmation step that shows the user the result.>
```

Rules:
- Slug must be lowercase, hyphen-separated (e.g. `my-skill`)
- Description must be one sentence, ≤120 chars
- Workflow steps must be numbered, starting at 1
- Every step that runs shell commands must include a fenced bash block
- The last step must confirm success to the user (show output or a status table)
- If a companion script exists, reference it as `bash "$SKILL_DIR/setup.sh"`

## 5. Write companion script (if requested)

If the user asked for a companion script, create `.claude/skills/<name>/setup.sh`:

```bash
#!/usr/bin/env bash
# <Skill name> — companion script
# Generated by create-skill meta-skill.
#
# Usage:
#   ./setup.sh           # default action
#   ./setup.sh --check   # check only, no changes

set -euo pipefail

# ---------------------------------------------------------------------------
# Config
# ---------------------------------------------------------------------------

# TODO: add environment-specific variables here

# ---------------------------------------------------------------------------
# Helpers
# ---------------------------------------------------------------------------

GREEN='\033[0;32m'; CYAN='\033[0;36m'; NC='\033[0m'
log() { echo -e "${CYAN}[<name>]${NC} $*"; }
ok()  { echo -e "${GREEN}[ok]${NC}    $*"; }

# ---------------------------------------------------------------------------
# Main
# ---------------------------------------------------------------------------

MODE="${1:-all}"

case "$MODE" in
  --check)
    log "Check mode — no changes made."
    ;;
  all|"")
    log "Running <name> setup..."
    # TODO: implement
    ok "Done."
    ;;
  *)
    echo "Usage: $0 [--check]"
    exit 1
    ;;
esac
```

Replace `<name>` placeholders with the actual skill name.
Make the script executable:
```bash
chmod +x .claude/skills/<name>/setup.sh
```

## 6. Register the skill in settings.local.json

Read the current `settings.local.json`:
```bash
cat .claude/settings.local.json
```

Add `"Skill(<name>)"` to the `permissions.allow` array if it is not already present.
Use the `Edit` tool to make a precise insertion — do not rewrite the whole file.

## 7. Confirm and show the result

Show the user what was created:

```bash
echo "=== Created files ==="
find .claude/skills/<name>/ -type f
echo ""
echo "=== SKILL.md ==="
cat .claude/skills/<name>/SKILL.md
```

Then tell the user:
- The skill is now available as `/<name>` in Claude Code
- If a setup.sh was generated, remind them to fill in the TODOs
- Suggest they invoke it once to verify it works
